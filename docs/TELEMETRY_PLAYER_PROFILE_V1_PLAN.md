## 本轮目标与边界

形成“实际游玩 → 完整事件 → 可核查指标 → 版本化画像”的本地闭环，为下一轮规则 DDA 提供可靠输入。

本轮交付事件、统计、画像和报告；运行时只观察，不调整难度。保持 v9 的物理、观察、动作、奖励及部署协议不变，不接入新的模型服务，不调用 LLM 生成玩家判断。DDA 和 Jev 留在后续独立迭代。

数据流：

```text
键盘 / Scripted / PPO / 路线重放
                 ↓
        原环境与确定性游戏核心
                 ↓ 每个物理 tick 的转移 + 入口生命周期
            Telemetry Recorder
                 ↓
   manifest.json + events.jsonl + episode 汇总
                 ↓
      离线特征统计 → PlayerProfile v1 → 审阅报告
```

## 迭代 1：协议与生命周期

先冻结三个独立版本：事件 schema、指标定义、画像算法版本。建议代码放入 `ai_platformer/adaptive/telemetry/` 与 `ai_platformer/adaptive/profile.py`；不把埋点代码散落到 renderer。

事件公共字段：schema_version、session_id、attempt_id、event_seq、player_id、actor_type、level_id、level 内容哈希、环境协议哈希、seed、物理 tick、决策序号、事件类型与 payload。actor_type 区分 human/scripted/ppo/replay；PPO 另外记录 checkpoint 哈希、推理后端和确定性模式。

- session 是一次游玩进程；attempt 是一次尝试，必须拥有独立 ID。核心的 `level_id:seed` 不能作为唯一尝试标识，因为重试会重复。
- 尝试结束原因区分 success、death、time_limit、restart、quit、level_switch、replay；中断不计作死亡，重复播放不自动计作玩家失败重试。
- 模拟时间用 tick 与固定频率计算，另记活跃墙钟时间和暂停时间；播放倍速不改变游戏内耗时。画像默认使用真人正常速度样本，其他样本分层展示。
- 明确一次尝试恰好开始一次、结束一次；reset、终局后重开和退出都不能重复结算。进程异常退出的未闭合尝试标记 incomplete，不补造结果。

**验收**：schema 校验能拒绝非法事件，重复同图同 seed 的尝试仍可区分；空会话、终局后退出、重开和异常尾部都有确定处理。

## 迭代 2：可靠事件采集与游玩入口接入

以 core 外部观察器接收每个真实物理 tick 的 before/action/StepResult，通过环境显式接入可选记录器；renderer 不负责推断碰撞或推进模拟。不开记录时保持原行为。

v1 事件范围：

| 类别 | 事件与证据 |
| --- | --- |
| 生命周期 | session/attempt 开始与结束、暂停/恢复、重开、切图、退出 |
| 运动 | 有效起跳、落地；记录起止位置、速度、按跳持续 tick；按键请求与实际起跳分开 |
| 收集 | coin_collected，包含实体 ID、位置、当前计数；来自 core 收集结果 |
| 交互 | 方块、道具、踩敌、受击、护盾等已有 core 事件，保留实体标识 |
| 结果 | 通关、死亡、超时、最大进度、最终位置；明确区分系统提供的死因与推测 |

优先接入 `play_level_spec` 的键盘入口，再接规则/重放与 `play_ppo`。PPO headless 用于自动验证采集正确性，真人入口用于真正收集玩家样本。默认不开训练环境的大量事件落盘。

关键实现要求：

- 逐 tick 获取事件，覆盖 action_repeat 中间帧发生的收集、交互与终局；不依赖当前只保留最后一帧的 info。
- JSONL 追加记录，配置缓冲与 flush；原子写汇总，读取时验证序号、身份、schema 和完整性。记录失败允许继续游玩，但清楚报告 telemetry 不完整并排除无效画像样本。
- 支持可选动作轨迹以做确定性重放；身份和墙钟字段不进入游戏状态哈希，事件存储不改变原 replay/protocol。
- player_id 使用本地显式选择的标识；没有稳定标识时只能生成当前会话画像，不默认把所有真人会话合并成同一人。

**验收**：开启/关闭采集的相同 seed/action 轨迹、奖励和终局一致；多事件中间帧不丢失、不重复；暂停、重开、切图和退出结果正确；记录开销单独测量并报告。

## 迭代 3：可复算的游玩指标

增加离线汇总入口，建议为 `scripts/summarize_play_sessions.py`，输出机器 JSON 和可阅读 Markdown。事件记录保持原始事实，指标能从事件重新生成。

第一版统计：

- 通关率、死亡次数、超时和中断次数；完成耗时、最大进度与单位模拟时间推进量。
- 同图失败后的真实重试数；死亡位置按地图/内容版本聚合，再按区域或 segment 汇总。
- 松果收集数量与比例；分母使用当前可玩区域的权威总数，零松果关卡显示不适用。
- 起跳次数、按跳持续时间分布、落地次数、空中占比、回撤距离及停滞时长；阈值显式版本化。
- 受击和踩敌等交互统计，未包含该内容的地图不计算相应能力分数。

不直接把“低收集率”解释成“不喜欢收集”，也不把“没有实际起跳的按键”直接当成操作错误。v1 只报告行为代理指标；偏好和错误归因需要可比场景、机会定义或玩家明确选择。

**验收**：手工构造轨迹与离线统计一致；事件计数和最终世界状态对账；不同 actor、地图版本及中断结果不混算；重复分析相同输入产出一致。

## 迭代 4：PlayerProfile v1

使用透明规则汇总近期有效样本，先建立多维画像，不压成一个不透明的总分。建议默认展示最近 10 次有效真人尝试，同时保留累计指标；窗口与规则版本写入输出。

画像包含：

- 身份和来源：player_id、样本范围、actor 过滤、地图与协议版本、生成时间。
- 行为维度：通过稳定性、推进效率、收集表现、跳跃控制指标、失败后重试行为。
- 证据量：有效尝试数、独立地图数、各维度可用样本与缺失原因。
- 状态：insufficient_data 或 ready，以及每个规则判断的输入、阈值和依据。

建议初始 ready 条件为至少 5 次有效尝试、覆盖至少 2 张可比地图；这是工程门槛，不声称统计置信度。维度没有相应场景时仍为 unknown，即便总体 ready。能力比较只在标注的可比内容分组内进行，避免把困难地图上的低成功率当成能力下降。

首版不推断人格或心理状态，不把所有未收集物视作可达的收集机会；无法区分偏好和能力时保留 unknown。训练、采样评估、固定动作重放默认不进入真人画像。

**验收**：样本不足不强行分级；可追溯每项指标到尝试记录；相同事件与同版本规则重建画像一致；混入 PPO/replay 样本不会改变真人画像。

## 迭代 5：小规模人工验收与阶段收尾

准备固定、已验证可玩的三类场景：平地收集、单障碍/短跳、障碍与缺口混合。优先复用现有 LevelSpec，不以当前 mixed_ground 三张诊断地图充当新的未见验收集。

开发侧先完成 scripted、PPO、失败/重开和暂停/退出的自动场景，再进行真人冒烟游玩。真人数据需要实际操作才能验证，不能用 PPO 代替。第一轮建议完成至少 6 次有效真人尝试并覆盖 3 类场景，另包含重开和暂停/退出流程；只用于管线验收，不声称验证了画像的普遍有效性。

收尾交付：事件样例、指标报告、画像报告、协议说明、重建命令、自动检查结果、人工检查记录与已知限制。训练/部署协议回归确认无变化；其他测试只按实际改动范围运行。

## 开发顺序与后续衔接

建议分三轮提交，便于逐轮审阅：

1. **Telemetry v1**：协议、逐 tick 采集、持久化、键盘入口与生命周期测试。
2. **Metrics + Profile v1**：统一入口接入、离线汇总、画像规则、重建与隔离测试。
3. **人工验收与收尾**：真实样本、报告、开销测量和兼容回归。

通过后再开发规则 DDA：只在尝试结束或下一关生成前读取画像，在已验证的 PCG 参数边界内产生可审计建议；先做固定难度对照与建议模式。有效后再定义“推进/收集/保守”等合法高级候选动作，评估 Jev 的接入价值。

本计划建议先审阅范围与指标口径，确认后从第一轮 Telemetry v1 开始实现。
